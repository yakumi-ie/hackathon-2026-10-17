# ハッカソン発表資料

[presentation.md](presentation.md) が Marp 形式のスライド。
7 枚、スライド説明約 2 分 55 秒＋デモ約 1 分 30 秒を想定し、5 分枠に約 35 秒の余裕を残している。
各スライドの HTML コメントに、話す内容と目安時間を入れている。
Marp の発表者ノートとして使える。

## 編集・プレビュー

VS Code の「Marp for VS Code」で `presentation.md` を開き、プレビューする。
内容の編集にはアプリ本体のビルドは不要。
Marp CLI が利用できる環境では、リポジトリのルートで次を実行して HTML を生成できる。

```sh
marp docs/presentation.md -o docs/presentation.html
```

PDF にする場合は次を実行する。
`--allow-local-files` は、資料から参照する手元のスクリーンショットを読み込むために指定する。

```sh
marp docs/presentation.md --pdf --allow-local-files -o docs/presentation.pdf
```

`docs/imgs/` の画像は相対パスで参照しているため、Markdown と画像を一緒に扱う。
生成した `presentation.html` / `presentation.pdf` は Git の管理対象から除いている。

## 発表の時間配分

| スライド | 内容 | 目安 |
| --- | --- | --- |
| 1 | 名前・コンセプト | 15 秒 |
| 2 | 課題と「次のメディア」への提案 | 30 秒 |
| 3 | 絞る → 眺める → 行く | 35 秒 |
| 4 | 既存データの活用と収録内容 | 30 秒 |
| 5 | 静的配信の構成 | 30 秒 |
| 6 | デモ導入 | 10 秒 |
| — | ブラウザで実演 | 90 秒 |
| 7 | 提案と次の検証 | 25 秒 |
| 合計 | | **4 分 25 秒** |

スライド 6 でブラウザへ切り替え、デモ後にスライド 7 へ戻る。
読み上げは目安なので、一度通して計時し、必要ならスライド 4・5 の説明を短くする。

## デモの準備

- 発表前にホストの開発サーバーを起動し、[localhost:3000](http://localhost:3000/) を開く。
- 初期状態を「上野駅 / 徒歩 1 km」に戻す。
  ページを再読み込みするとこの状態になる。
- Chrome のデバイスツールなどで 390 × 780 px 相当の表示を用意し、発表中に設定を変えずに済むようにする。
- 背景地図とサムネイルが表示され、上野駅で徒歩 11 本・車 47 本になることを事前に確認する。
- 発表用の位置取得にはデモ地点を使い、ブラウザの許可ダイアログを出さずに進める。
- 動画は再生せず、視聴への導線を紹介する。
  経路リンクで開く別タブから、アプリへ戻れるようにしておく。

## デモの操作（約 90 秒）

| 経過 | 操作 | 話すこと |
| --- | --- | --- |
| 0〜15 秒 | 上野駅・徒歩 1 km の状態を示す | 現在地の代わりにデモ地点で試せる。半径で絞り込んでいる。 |
| 15〜35 秒 | 「動画を眺める」を選び、一覧を少しスクロール | 11 本が近い順に並び、動画のサムネイルから探せる。 |
| 35〜55 秒 | 最初のカードの「地図で見る」を選ぶ | 上野駅の掲載地点と名称を確認できる。ピンとカードは共通の番号。 |
| 55〜70 秒 | ピン内の「動画カードを見る」から戻り、「掲載地点への経路」を開く | 座標と移動手段を渡して、Google マップで経路を確認する。 |
| 70〜85 秒 | アプリへ戻り、ページ上部で「車 10 km」を選ぶ | 範囲を広げると 47 本になる。地図と一覧も同じ条件で更新される。 |
| 85〜90 秒 | スライドへ戻る | まとめへ進む。 |

通信や画面共有で手間取ったら、経路の別タブ表示を省略する。
アプリを開けない場合は、スライド 3 の実画面を使って「絞る・眺める・行く」を説明し、そのままスライド 7 へ進める。
